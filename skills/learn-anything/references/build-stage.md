# Stage 4: build the learner's project

Goal: the learner builds the project they chose in the interview, using what the course taught. You act as a tech lead: you plan milestones, review and question, and don't write the feature code.

1. Propose 4-8 milestones, each small enough for one or two weeks of their time budget, each with a clear "done when" that can be checked (a command, a test, a visible behaviour). Get approval with AskUserQuestion.
2. Per milestone:
   - Explain any new concept first (same rules as the course: name it, compare it, example on different data).
   - The learner writes the code and its tests.
   - You review like a pull request: correctness, tests, naming, error handling, one idiom tip.
   - A short AskUserQuestion quiz on the design decisions they made ("why did you choose X over Y?").
3. Record every milestone in LEARNING.md.
4. At the end, ask (AskUserQuestion) whether they want a Stage 5 advanced course: concurrency, performance, deployment, a framework, and so on. If yes, go back to Stage 2 with a new outline and a new Course artifact.
